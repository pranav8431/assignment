# Part 5 — Stakeholder Slack Message

Two things shaped this.

The brief says the delay follows the Part 3 fixes, so the message explains the new automatic check
rather than the original data problems. And it says the manager forwards it to a client unchanged, so
it stays on what the check guarantees from now on rather than volunteering that earlier scores were
wrong.

That second one is a deliberate call. It's true that earlier scores were affected, and I've left it
out anyway, because it raises a question the manager can't answer in a document they can't edit. If a
client asks directly, that's a conversation with someone who can handle it, not a line in a forwarded
Slack message.

---

> **Heads-up: churn scores moving to Wednesday this cycle**
>
> Hi — a quick note on timing. Churn scores will arrive **Wednesday instead of Monday** this cycle,
> a two-day shift.
>
> Here's why. We've added an automated quality check that now runs before scores are published.
> Every batch of transaction data has to clear it — no duplicated records, no refunds miscounted as
> purchases, nothing missing — and anything that fails is held back and corrected rather than passed
> through. That check is what takes the extra two days.
>
> The benefit is straightforward: from this cycle onward, every score is built only on transactions
> we've verified. Nothing else in your reporting is affected, and this is a one-time shift while the
> new check beds in — we're back to the usual Monday delivery from the next cycle.
>
> I'll confirm as soon as Wednesday's run is out. Happy to walk through it any time.

---

*150 words.*
